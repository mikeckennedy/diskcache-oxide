## Checked and Found Sound

- **Step 10 M1 refinement (`Transaction::__exit__` for `TxState::PassThrough`, `crates/diskcache-oxide-py/src/cache.rs:2483-2492`):** Verified by line-by-line trace and five live subprocess probes on `3ca85e87` (3.14). `TxCache::Shard(cache, shard).handle()` returns `cache.get().shard_handle(*shard)`, so `self.cache.handle().store.check_usable()` checks the exact shard the block belongs to. Live probes confirmed all five cases: (1) `FanoutCache` nested `transact(key=k0)` with outer open at fork raises `ForkedInsideTransactionError` on inner exit while another shard (`k1`) still reads and writes; (2) `FanoutCache` nested `transact(key=k0)` whose outer ended before fork succeeds (`False`, `Done(committed)`) in the child even while another shard (`k1`) is held open across the fork and poisoned; (3) grandchild leaving a grandparent-entered nested block whose outer was open at fork 1 raises `ForkedInsideTransactionError`; (4) grandchild leaving a grandparent-entered nested block whose outer ended before fork 1, after child 1 opened a new transaction and forked grandchild 2, raises `ForkedInsideTransactionError`; and (5) cross-thread `PassThrough` entered on Thread B (which ended its outer transaction out of order before Thread A forked) exits cleanly in the child. Also verified by trace that an outer transaction in `Ending` or rolled back with a lent/parked connection at the fork still poisons the store, so `store.check_usable()` refuses the nested exit.
- **Step 10 L1 refinement (`poison::refuse_if_nothing_is_usable`, `fanout::open_manifest`, `Store::open_until`, `layout::resolve`):** Verified by line-by-line trace across every directory-creating path in `crates/diskcache-oxide-core/`. `fanout::open_manifest` calls `refuse_if_nothing_is_usable()` before `ensure_directory(root)` and before any temp file, `link`, or parent-directory `fsync`. `Store::open_until` calls it on the plain-cache branch before `ensure_directory` and `refuse_manifest`. `layout::resolve` runs `attempt(root)` first and propagates `Error::Unusable` immediately on line 187, never reaching `create(&sub)` on line 189 when `all_unusable()` is set. Every Python `FanoutCache`, `Caches`, and `DjangoCache` shard open goes through `fanout::open_manifest` and `Store::open_shards` (whose gate-held pre-check calls `check_usable_at` -> `check_usable_opt` before any shard's `open_until`). (Minor observation only, not a finding: a direct Rust caller of the public `Store::open` / `Store::open_until` passing `Role::Shard` while bypassing both `open_manifest` and `open_shards` would run `ensure_shard_directory` before `open_store` -> `check_usable_at`; no path in Python or `open_shards` can reach this, and it is not worth touching shipped code or restarting the gate.)
- **Test-only thread-local (`poison::PRETEND_NOTHING_IS_USABLE`) and wiring tests (`fanout.rs`, `store.rs`):** Verified `PRETEND_NOTHING_IS_USABLE` is strictly behind `#[cfg(test)]` in `diskcache-oxide-core` only and cannot affect production builds or `diskcache-oxide-py`. Both `fanout::tests::a_process_that_can_use_no_cache_creates_no_root` and `store::tests::a_process_that_can_use_no_cache_creates_no_directory_for_a_new_one` exercise the real `open_manifest`, `Store::open`, and `Store::open_resolving` entry points and assert that no directory is created, proving the wiring rather than only the helper.
- **Step 10 tests on `3ca85e87` (macOS arm64):** Ran `cargo test -p diskcache-oxide-core --lib a_process_that_can_use_no_cache` (2 passed) and `pytest tests/unit/test_fork_inherited.py` on both 3.14 (`venv/`, 16 passed) and 3.14t (`.venv-ft/`, 16 passed).
