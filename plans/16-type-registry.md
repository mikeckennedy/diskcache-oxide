# Plan 16: a type registry for the codecs

A way to tell the codec how to store a type it doesn't know, without pickle. Prompted by what the Talk Python apps actually put in their caches (Michael, 2026-11-06): Training's three values that oxide refuses today are all foreign types (a bson `ObjectId` inside the session dict, markdown_subtemplate's `CacheEntry` namedtuple, markdown2's `str` subclass), and Talk Python to Me converts dataclasses to dicts by hand at four sites. A dunder protocol on the class can't reach any of the foreign ones; a registry the caller fills can reach all of them, and it covers the dataclass case too. Decisions settled in the interview are marked. `the-rust-architect` reviewed the plan on 2026-11-06 (14 findings, folded in below; the review's verification that a pre-plan build already reads a `$t:` row as `ForeignValueError` is noted in section 4).

## 1. Decisions (Michael, 2026-11-06)

- **Scope: global, with a per-cache override.** `diskcache_oxide.register_type(...)` applies to every cache in the process. `Cache(types=...)` and `FanoutCache(types=...)` take a `TypeRegistry` consulted before the global one, for a handle that needs a different encoding of the same type. A registered type is a property of the process's code, not of one directory.
- **Subclasses of built-ins stay a `TypeError`.** A namedtuple coming back as a plain tuple is the quiet coercion the codec was built to refuse. Register the type, or convert at the call site.
- **Dataclasses get a default.** `register(Episode, name='tp.Episode')` with no `encode`/`decode` walks the fields in Rust on the way in, with no intermediate dict, and calls `Episode(**fields)` on the way out, so defaults and `__post_init__` still run. Explicit functions override the default.
- **The tag name is explicit and required.** `register(ObjectId, name='bson.ObjectId', encode=str, decode=ObjectId)`. A class rename or module move never orphans existing rows, because the name is the caller's, not the class's. Decode looks the name up in the registry; an unknown name is a `ForeignValueError`, never an import. That is the whole difference from pickle.
- **Dispatch order (Michael's question, "what if a registered type is also something the codec could encode"):** exact built-in checks first, then the registry by exact `type(o)`, then the pickle fallback if the cache has `pickle=True`, then `TypeError`. The codec's own exact types can't be registered (section 3), so the order never changes a result, only the cost: a plain `dict` or `str` pays nothing new. A `dict` subclass never matched the exact checks, so registering it just works. No MRO walk: a subclass of a registered type is its own registration.
- **Settled after the architect's review (Claude, for Michael to confirm):** an error raised from a registry hit never falls through to pickle, even on a `pickle=True` handle (section 5); a decode function's `TypeError` or `ValueError` deletes the row under `on_decode_error='miss'` (section 5, finding 3); **Naming (Michael, 2026-11-06, after finding 14):** `register_type`, `unregister_type`, `registered_types()` and the global instance `diskcache_oxide.registry`, since `register` next to `Caches.register` and `types` next to the stdlib module read badly; the class is `TypeRegistry` and the constructor keyword stays `types=`.

## 2. What exists today

- `codec::encode` (`crates/diskcache-oxide-py/src/codec/mod.rs`) picks the serializer, tries it, and on `TypeError` pickles if `pickle=True`. `msgpack::encode` and `json::encode` dispatch on exact type (`cast_exact`, `is_exact_instance_of`) and end in `common::unsupported(o)`, the `TypeError` D-001 promises. `too_deep()` and `unsupported_len()` are `TypeError`s too, so they also fall to pickle today.
- **The encoder runs no user Python code.** The module docstring promises it, and `common::DictEntries::of` relies on it: on the GIL build a dict is iterated in place, "since it calls only C methods that never release it", while the free-threaded build copies the entries under one critical section because another thread can resize the dict between steps. Sets are collected before any child is encoded, tuples are immutable, lists are read by index with a changed-during-encode check, and JSON's list iterator re-checks its length. Dicts are the one place where user code running mid-iteration would panic PyO3's iterator and turn `set` into a `PanicException`. This plan is the first thing to put user code inside the encoder.
- Anything the format would change is written as a one-entry map whose key is a tag: `$bytes`, `$tuple`, `$dict`, `$float`, `$int`, `$datetime`, `$date`, `$decimal`, `$set`, `$frozenset` (`codec/common.rs`). A user dict whose first key starts with `$` is wrapped in `$esc`, so the whole `$` namespace is reserved (`tests/unit/test_codec.py` pins the escape). Both formats share the names; msgpack writes a UTC datetime as the timestamp extension instead. `Tag` is a `Copy` enum and `Tag::parse` is a closed match; an unknown `$` key is a `ForeignValueError` raised where the key is read (`msgpack.rs` `map()`, `json.rs` `KeySeed::visit_str`).
- Decode runs where the value is: `get` decodes an inline value from SQLite's row buffer while the connection is held, and a pickle hook that re-enters the cache is safe because a nested operation never waits on its own thread (plan 00, Phase 1 notes; review 07). A slow decoder keeps a connection, a gate level and a read snapshot for as long as it runs. The gate level a hook holds through a pending fork is D-027.
- **Decode errors today.** `as_corrupt` (`mod.rs`) wraps anything a decoder raises into `CorruptValueError` with the original as `__cause__`, exempting only `CorruptValueError` (so `ForeignValueError`, which subclasses it), `MemoryError`, `RecursionError` and non-`Exception`s. `classify` in `cache.rs` then decides: `Passthrough` (raised, row kept) for non-`Exception`s and `UnsafeValueError`; `Foreign` (miss, row kept) for `ForeignValueError`; `Unreadable` (miss, row deleted, reported once per stored version) for `CorruptValueError`; and for a pickle row anything but `MemoryError`, `RecursionError` and `OSError` is `Unreadable` while those three pass through. On a `durable=True` handle an `OSError` from a hook is a miss with the row kept (D-028). `as_corrupt`'s short exemption list was fine while no user code ran inside the msgpack and JSON decoders; a registered decode function makes `OSError` and `UnsafeValueError` reachable there, and today they would be wrapped and the row deleted.
- `common::Types` caches the Python objects the codecs need, once per interpreter, in a `PyOnceLock`. The registry is the first per-process state the codecs have that can change after import.
- `HandleConfig` in `cache.rs` holds `serializer` and `pickle` and has a `traverse` for the GC; `Cache` is `#[pyclass(frozen, module = "diskcache_oxide")]`. `Caches.register(name, **kwargs)` forwards constructor keywords; `NullCache` accepts and ignores every `Cache` keyword; `tests/unit/test_stubs.py` checks `_core.pyi` against the compiled signatures and fails the moment the module exports a name the stub doesn't list.

## 3. The Python surface

```python
import diskcache_oxide
from bson import ObjectId

diskcache_oxide.register_type(ObjectId, name='bson.ObjectId', encode=str, decode=ObjectId)
diskcache_oxide.register_type(CacheEntry, name='mst.CacheEntry', encode=tuple, decode=lambda t: CacheEntry(*t))
diskcache_oxide.register(Episode, name='tp.Episode')  # a dataclass: fields in, Episode(**fields) out

reg = diskcache_oxide.TypeRegistry()  # for one handle; consulted before the global one
reg.register(ObjectId, name='bson.ObjectId', encode=lambda o: o.binary, decode=ObjectId)
cache = Cache(path, types=reg)
```

- `register(cls, *, name, encode=None, decode=None)`: `cls` must be a class, `name` a non-empty `str` that `to_str()` accepts (a lone surrogate fails here, not at the first `set`). `encode` is called with the instance and returns any value the codec can already store, registered types included. `decode` is called with that value back and returns the instance. Both given, or neither; neither is allowed only for a dataclass (section 6). A class that is one of the codec's own exact types (`str`, `bytes`, `int`, `float`, `bool`, `NoneType`, `list`, `tuple`, `dict`, `set`, `frozenset`, `datetime`, `date`, `Decimal`) raises `ValueError`: the wire form of a built-in is a contract across versions and processes, and a process that changed it would write rows no other process could read. Subclasses of those are fine; that is how a namedtuple or a `str` subclass gets in.
- **One implementation.** All validation and the dataclass introspection live in Rust, in `TypeRegistry.register` (registration isn't a hot path; it imports `dataclasses` and calls `fields()`). The module-level `register_type`, `unregister_type` and `registered_types` in `__init__.py` are one-liners on the global instance, `diskcache_oxide.registry`, so `reg.register(...)` and `diskcache_oxide.register_type(...)` can't drift apart.
- **Last registration wins**, by class and by name, in one atomic replacement of the snapshot. Registering a class again replaces its entry; registering a name that another class holds moves the name, and encoding the old class is a `TypeError` from then on. No error, because a dev reloader builds a new class object with the same name on every reload, and a `ValueError` there would break every reload. `unregister(cls)` removes an entry; `registered()` returns `{name: cls}` (module level: `unregister_type`, `registered_types`) for introspection and tests.
- A handle's `types=` registry is consulted first on encode (by class) and on decode (by name), then the global one. A `TypeRegistry` can be passed to several handles. `NullCache` accepts `types=` and ignores it. `Caches.register(..., types=reg)` forwards it like any other keyword.
- Typing: `register` is generic in `T`: `encode: Callable[[T], object]`, `decode: Callable[[object], T]`. `CacheLike` doesn't change; the registry is construction-time only.

## 4. The wire format

A registered value is the same one-entry tag map the codec already uses, with the key `$t:` followed by the registered name and the body being whatever `encode` returned, encoded by the normal path:

```text
{"$t:bson.ObjectId": "672b1c9e1f4a2b3c4d5e6f70"}
{"$t:tp.Episode": {"id": 491, "title": "...", "published": {"$datetime": "..."}}}
```

- Both serializers use it unchanged. No built-in tag starts with `$t:` (`$tuple` is `$t` followed by `u`), the `$` namespace is already reserved and escaped so no user dict can collide, and the fixed prefix keeps registered names apart from the built-in tags whatever they are called. A map with a `$t:` key and more than one entry stays corrupt, as for any tag; an empty name after `$t:` is foreign and is never written.
- The body re-enters the encoder at `depth + 1`, so an encode function may return a value holding other registered types, nested, and a function that returns an instance of its own type recurses until `MAX_DEPTH` and fails with the existing too-deep `TypeError` rather than a stack overflow (`check_stack` runs per container as now). Section 5 says why that `TypeError` doesn't reach pickle.
- Existing rows don't change. The mode column stays 3 or 4. **Verified by the architect on the current build:** a `$t:bson.X` row decodes today, in both formats, as `ForeignValueError: unknown tag "$t:bson.X"`, so a build without this plan reads the new rows exactly as foreign and keeps them.
- Not a format change: the manifest and `FormatMismatchError` are untouched. Any later change to the `$t:` scheme would be one.

## 5. Encode and decode in Rust

- **Registry storage.** `TypeRegistry` is `#[pyclass(frozen, module = "diskcache_oxide")]`, like `Cache`, holding an `ArcSwap<RegistryMap>` (`arc-swap`, MIT/Apache-2.0, dependency-free; one line in `[workspace.dependencies]` with a comment like the others, and `deny.toml` passes as is). `ArcSwap` is interior-mutable, so `frozen` works and there is no borrow flag on 3.14t. `RegistryMap` is two `HashMap`s over the same `Arc<Entry>`s: by `TypeAddr(usize)`, a newtype over `ty.as_ptr().addr()` whose doc comment says why it is safe (the entry owns a strong `Py<PyType>`, so the address can't be reused while registered, and a reader's snapshot keeps an old `Arc` alive so a type can't be freed under an in-flight encode), and by name. `Entry { ty: Py<PyType>, name: String, kind: Explicit { encode: Py<PyAny>, decode: Py<PyAny> } | Dataclass { fields: Vec<Py<PyString>> } }`. Readers call `load()` once per cache call and keep the guard for the call (not `load_full`); writers use `rcu` (load, clone, change, compare-and-swap, retry), so there is no writer mutex at all. With last-wins semantics a retried closure is harmless, and registrations are rare. Reads are lock-free, which matters on 3.14t where encode runs on every thread, and the hot path for built-ins never reaches the lookup (section 1).
- **GC.** `TypeRegistry` holds types and closures whose `__globals__` can refer back to the registry or to a cache, a cycle. It gets `__traverse__` (load the snapshot, visit every entry's type and functions) and `__clear__` (store an empty map), and `HandleConfig::traverse` visits the handle's `types`.
- **The `Codec` context.** `HandleConfig` replaces its `serializer` and `pickle` fields with `codec: Codec { serializer, pickle, types: Option<Py<TypeRegistry>> }`, which is `Sync` (`Py<_>` and `ArcSwap` are), with `refuses(mode)`, `encode(py, value)` and `decode(py, mode, stored)`. `read_row`, `pop_value` and `decode_value` in `cache.rs` capture `&self.codec` instead of `allow_pickle`. A per-call `Snapshot<'a>` (the handle's guard and the global's) is built once at the top of `set`, `add`, `read_row` and the pop fallback, so a registration during a call doesn't change the format mid-row, and is passed by reference: bundled with `&Types` into an `EncodeCtx` for msgpack's `encode` rather than a fifth parameter, in JSON's `Ctx` and `DeCtx`, and as a `reg` field on msgpack's `Reader`. `fanout.rs` changes only in its constructor and traverse. `_core._encode` and `_core._decode` (the test hooks) take an optional `types=`.
- **Encode.** After the exact checks fail and before `unsupported`: `type(o)` lookup in the handle's snapshot, then the global. On a hit: write the tag head, then for `Explicit` call `encode(o)` and encode the result at `depth + 1`; for `Dataclass` write a map of `len(fields)` entries, each `getattr(o, field)` encoded at `depth + 2` (the map and the tag wrapper both count). **Dict iteration becomes a copy whenever user code can run:** `DictEntries::of` takes a `may_run_user_code` flag, true when either snapshot has any entry, and copies the entries into a `Vec` on every build when it is set. A process with no registrations keeps today's in-place path and cost on the GIL build. The module docstring in `mod.rs` changes from "runs no user Python code" to name the two places it does (the pickle fallback and a registered type).
- **Errors from a registry hit never fall to pickle.** Today `codec::encode` pickles on any `TypeError` when `pickle=True`, which would silently pickle a self-returning encode function (too deep), an encode function that raises `TypeError`, and a registered dataclass with one unstorable field. The user registered the type precisely to stay off pickle, and the fallback would hide a bug. So a registry hit marks its errors (a thin wrapper type the serializer unwraps at the top), the fallback triggers only for the plain `unsupported` path, and the marked error is raised from `set` as it is, with nothing written. The docs state it: with `pickle=True`, a registered type is encoded through the registry or fails, never pickled.
- **Decode.** `Tag::Custom(Arc<Entry>)`, resolved where the `&str` is in hand (`msgpack.rs` `map()`, `json.rs` `KeySeed::visit_str`) by looking the name up in the handle's snapshot, then the global; `Tag` stays `Copy`-cheap (an `Arc` clone) and allocates nothing per value. Unknown: `foreign("unknown tag ...")` right there, which is today's flow and message, so the row is kept under `on_decode_error='miss'` and the message names the tag. For `Explicit`: decode the body to a Python value, call `decode(value)`. For `Dataclass`: the body must be a map with `str` keys; build a kwargs dict and call `cls(**kwargs)`. A missing key is left to the constructor's defaults; an unknown key makes the constructor raise `TypeError`.
- **An exception from a decode function** is classified by one helper at the registry call site that mirrors `classify`'s pickle branch: non-`Exception`s, `MemoryError`, `RecursionError`, `OSError` (`Timeout` included), `UnsafeValueError` and `CorruptValueError` pass through unchanged; everything else (a `TypeError` from an old-shape row, a `ValueError` from the function) becomes `CorruptValueError` with the original as `__cause__` and a message naming the tag. `as_corrupt` gains `OSError` and `UnsafeValueError` to its exemption list, which changes nothing for existing rows since neither could arise from the decoders before. The consequences, through the existing `classify`: a passed-through `OSError` or `RecursionError` is raised with the row kept; on a `durable=True` handle outside its own transaction it is a miss with the row kept (D-028); `UnsafeValueError` raises; the wrapped `CorruptValueError` is a deleted miss under `'miss'`, reported once per stored version, and raises under `'raise'`.
- **Why delete the row (the question left open in the first draft, settled with the architect):** it matches the pickle branch of `classify` and D-026's "a value no build can read is still deleted"; keeping the row buys no self-healing, since a miss already makes the app rewrite the key, while it costs a failing decode plus a Python call on every read and goes silent after the first report; and the two risk cases (a buggy decode deploy empties that type's rows; two handles with different registrations ping-pong) are the ones the pickle path already accepts. One deliberate difference from pickle, to state in D-041: under `'raise'` the caller sees `CorruptValueError` with their own exception as `__cause__`, whereas an unpickling error passes through unchanged. One type then means "this build can't read this row", and the message carries the tag.
- **Where it runs.** Decode runs where pickle runs now, with the connection held. A decode function that re-enters the cache is safe for the reason a pickle hook is: a nested read of a foreign key keeps the outer row; a nested read of a corrupt key raises `CorruptValueError` through the decode function, which counts as the outer row's, so the outer row is deleted under `'miss'` (the pickle branch does the same, and the test pins it). The docs say what a slow decoder costs, in the same words as for pickle.
- **Fork.** A child inherits the snapshot as of the fork. `arc-swap` keeps per-thread debt nodes in a global list; in a child, dead threads' nodes stay marked in use, and a later `store` pays their debts by over-incrementing the old map's `Arc`, a leak of one old map, harmless. What the plan can't confirm from the crate's source is that a writer never spins on a reader caught mid-`load` at fork time, so section 8 tests registering in the child under a deadline, not only reading. `std::sync::RwLock<Arc<Map>>` would be worse here: a reader count stuck from a dead thread hangs every later write forever. That is why there is no lock at all.

## 6. The dataclass default

- At `register(cls, name=...)` with neither function, `TypeRegistry.register` checks `dataclasses.is_dataclass(cls)` (a `TypeError` otherwise, naming what to pass) and keeps the names of the `init=True` fields, in order, as interned strings. `init=False` fields are derived state the constructor recomputes, so they aren't stored; `ClassVar`s aren't fields. A `__post_init__` runs on decode because the constructor runs.
- **`InitVar` is refused.** `fields()` omits `InitVar` pseudo-fields, so a dataclass with a required `InitVar` would register fine and then fail every decode with `TypeError`, deleting rows. `register` inspects `cls.__dataclass_fields__` for `_FIELD_INITVAR` entries and raises `TypeError` naming the field and "register with explicit functions".
- Slots dataclasses work: `getattr` doesn't care. Frozen ones work: the constructor is the only writer. A field whose value isn't storable fails at `set` with the existing `TypeError`, naming the value as now, because the field walk just recurses; by section 5 that error never reaches pickle.
- Registering a dataclass whose field is another dataclass needs that one registered too, by the exact-type rule. The error at `set` is the normal `TypeError` for the inner value, and the docs say so.
- Schema change: a field added with a default decodes an old row fine; a required field added makes the constructor raise on the missing kwarg; a field removed makes it raise on the unexpected kwarg. Both are a deleted miss under the default, and the writer replaces the row. Section 8 tests both shapes.
- Not covered on purpose: Pydantic (`model_dump`/`model_validate`), attrs, `TypedDict`. Each is one explicit `register` call, shown in the guide; the library learns no third-party shapes.
- The point of the default is ergonomics first and the write path second: `asdict()` deep-copies, the field walk doesn't. Decode still builds one kwargs dict and calls the constructor, so a read saves little. The guide says exactly that, with a number from step 8.

## 10. Risks and open questions

- **A per-handle registry is a foot-gun across processes.** Two processes with different registries on one directory write rows the other can't read. That is the same class of problem as two processes with different `serializer=` settings, which the design already accepts. The docs say: register at import time, in every process, the same way.
- **User code inside the encoder** is the real change this plan makes, and the two must-fix findings were both about it. Besides dicts, the places audited and found safe: sets (collected first), tuples (immutable), lists (indexed with a change check), JSON's list iterator (re-checks length). Anything new that iterates a container in the encoder must take the same care.
- **`arc-swap` under fork** is the one claim the plan makes about a dependency's internals without reading them; the fork test in section 8 is what stands in for that reading. If it hangs, the fallback is an `AtomicPtr<Arc<RegistryMap>>` with a manual leak-and-swap, a page of unsafe in the one place `#![deny(unsafe_code)]` already makes exceptions for.
- **The dispatch cost for refused values.** A `TypeError` now costs two hash lookups more. Nobody runs on that path.
- **Decode with the connection held** is the same trade pickle makes, and the same docs sentence covers it. A decode function that does I/O is the user's problem, named in the guide.
- **Not in scope:** registering by protocol or ABC (no MRO walk, by decision), auto-registering every dataclass (decode needs an allowlist, and the name is explicit by decision), a `register` decorator form (a one-line follow-up if wanted), encoding `init=False` fields.
