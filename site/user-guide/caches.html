Caches: named caches

An app with more than one cache ends up writing the same code to manage them: map names to directories, open each one once and reuse it, carry on with caching switched off when one can’t be opened, turn some off for a load test, and show counts and sizes on an admin page. Caches is that code.

from diskcache_oxide import Caches

caches = Caches('/var/cache/my-app', timeout=1.0, on_decode_error='miss')
caches.register('general')
caches.register('pages', size_limit=2 * 2**30)

caches['general'].set('greeting', 'hello')
caches['pages'].get('/about')

Settings passed to Caches apply to every cache, and register can override them for one. Each cache lives in a directory named after it under the base directory, unless you pass directory=.

One setting works differently here: a function passed as on_decode_error is called as report(name, key, exc), with the cache’s name first, so one reporter can serve every cache. (On a plain Cache it’s report(key, exc).) A function that doesn’t take three arguments is rejected when you create the registry or register the cache.

Lookups

A cache opens on its first lookup, and every lookup after that returns the same object. A lookup is a single dict read with no lock, so it’s fine to do on every request rather than keeping your own references. Lookups are safe from any thread, on free-threaded Python too, and in a child process after a fork.

Caches is generic in its names. Give it a Literal and a misspelled name becomes a type error:

from typing import Literal

CacheName = Literal['general', 'pages']
caches: Caches[CacheName] = Caches('/var/cache/my-app')
caches['genral']  # ty: invalid argument

When a cache can’t open

A cache can fail to open: a permissions problem, a disk that went away, a database written by a newer version, or another process holding the lock for longer than timeout. A lookup then returns a NullCache instead of raising, so the request carries on without the cache. The error goes to on_open_error(name, exc), which logs it at ERROR on the diskcache_oxide logger by default. Pass your own function to send it to Sentry or your logging setup.

The failure is remembered for retry_open_after seconds (10 by default), so a broken cache costs one failed open every 10 seconds, not one per request, and the lookup after that tries again. A cache that recovers is picked up without a restart. Under load, several threads may make that retry at the same moment, and each one that fails reports it.

MemoryError isn’t an open failure, so it raises from the lookup, as it would from Cache(...). That includes SQLite running out of memory while opening (SQLITE_NOMEM), which used to be an OSError and got a NullCache.

A Timeout at open means busy, not broken: another process holding the lock, or a first lookup that collided with a fork. It’s remembered for at most 1 second, and the default report is a WARNING with no traceback. A custom on_open_error still gets the exception. Lookups of a cache that’s already open never touch any of this.

A bad setting (size_limit=True, serializer='yaml') is a bug, not an outage, so it raises on lookup instead.

Switching caches off

caches.disable('pages')   # later lookups return NullCache(invalidate=real)
caches.enable('pages')
caches.enabled('pages')   # False while it's off

While a cache is disabled, its lookups return NullCache(invalidate=real): reads miss and writes are dropped, but delete and clear still reach the real cache, so entries you invalidate by removing them aren’t served stale when it comes back on. Invalidating by writing doesn’t survive: an overwriting set or a version-bump incr is dropped like any other write, and the old value is served again (see Keep invalidating while caching is off). Switches only change later lookups. Code that already holds the real Cache keeps using it, so set them at startup, before you hand caches out.

If your app has its own names for what it caches (Talk Python calls them purposes), map them onto registered caches in your own code. It’s a few lines:

PURPOSES = {'rss_feed': 'general', 'episode_html': 'episodes'}
off = {'rss_feed'}  # from your settings file

def cache_for(purpose: str) -> CacheLike:
    real = caches[PURPOSES[purpose]]
    return NullCache(invalidate=real) if purpose in off else real

Build the wrapper on each call rather than memoizing it: caches[...] is already cheap, and a memoized NullCache(invalidate=...) wrapped around a cache that had failed to open would never pick up its recovery.

Admin and shutdown

caches.stats()                      # {name: CacheStats(name, directory, enabled, count, volume, error)}
caches.clear('pages', timeout=10)   # works on a disabled cache too
caches.expire_all(timeout=10)       # {name: removed, or None if it failed}
caches.close_all()                  # at shutdown; `with Caches(...) as caches:` does it too
  • stats() opens every registered cache and never raises: a cache that can’t be read has its error set.
  • clear(name) raises if the cache can’t be opened, so an admin page doesn’t report “0 cleared” for a failure.
  • expire_all() runs every cache, logging and reporting None for one that fails. Run it from a scheduled job rather than inside a request: a large expire takes seconds.
  • Maintenance calls hold the write lock once per chunk, so give them a longer timeout= than the request path’s.

Coming from DurableCache

Talk Python’s apps wrap diskcache in a DurableCache class and a cache_service module. Each piece now has a home in the library:

DurableCache / cache_service diskcache-oxide
bool() is always True Cache is always truthy (D-009); NullCache is falsy
CacheProtocol CacheLike
NullCache, PerfTestNullCache NullCache, and NullCache(invalidate=real)
get that logs, deletes and misses on any error Cache(on_decode_error='miss') or a reporting function (details)
A cache that can’t take a request down Caches(base_dir, durable=True), which also covers set, whose failures DurableCache raises (details)
create_cache(name, size_limit) caches.register(name, size_limit=...), then caches[name]
timeout=1.0 on every open Caches(base_dir, timeout=1.0)
A NullCache when opening fails the same, reported through on_open_error and retried after 10 s
get_all_caches(), clear_*(), close_all_caches() caches.stats(), caches.clear(name, timeout=...), caches.close_all()
A separate maintenance handle with a 10 s timeout timeout= on clear(), expire() and cull()
Hourly expire_all_caches() inside create_cache caches.expire_all() from a scheduled job

The library’s self-healing read is safer than the wrapper’s in three ways:

  • It deletes only what failed. The wrapper’s get-then-delete can remove a fresh value another process wrote in between. The library deletes exactly the stored version it couldn’t read.
  • It never waits to clean up. If the write lock is busy, the bad row stays and a later read tries again.
  • It doesn’t hide outages. The wrapper catches every exception, so a lock Timeout also became a silent miss. In the library, Timeout, I/O errors and MemoryError still raise by default, and so does reading a pickled value from a cache without pickle=True, which is a configuration mistake. durable=True is how you choose a miss for an outage, and it counts each one and logs them, at most once a minute, rather than staying silent; MemoryError and that mistake raise regardless.

What stays in the app: reading its settings file and environment variables (pass the result as base_dir), its purposes and their on/off flags, descriptions for the admin page, and wiring the reporting functions to Sentry or logbook.
